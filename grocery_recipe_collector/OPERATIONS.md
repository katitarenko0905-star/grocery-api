# Запуск и обновление каталога продуктов

Этот репозиторий содержит сборщик и отдельный read-only API. Само приложение «Ладно», база PostgreSQL и интеграция с ней находятся в закрытом репозитории GF, `integrations/local-grocery/OPERATIONS.md`. Клонируйте оба репозитория рядом и выполняйте команды из `grocery-api/grocery_recipe_collector/`, если не указано иное.

## Требования и запуск API

Нужны Docker с Compose, Python 3 и доступ к интернету. Наличие Docker-образа Camoufox не гарантирует доступ к сайтам. Если приложение ещё не запущено, сначала выполните инструкцию GF; этот API самостоятельно его не поднимает.

```sh
cd grocery-api/grocery_recipe_collector
docker compose -p grocery-api -f compose.catalog.yml up -d --build
curl -fsS http://127.0.0.1:18082/health
```

Страница — http://127.0.0.1:18082/browse; описание API — [API.md](API.md). Compose монтирует в режиме чтения именно `data/ladno_2026-10-27/catalog.json.gz`; это сохранённый снимок, а не автоматически обновляемая база приложения. Для нового запуска с другим снимком измените путь к volume через отдельный Compose override, затем пересоздайте сервис. Удаление контейнера не удаляет файл выгрузки.

## Выгрузка рецептов и сбор карточек

```sh
python3 catalog.py export-app --base-url http://127.0.0.1:18081 --out data/new_run
```

Команда получает опубликованные рецепты и ингредиенты приложения, не товары магазинов. Далее нужны найденные официальные карточки в файлах `data/new_run/evidence/search_*.json`: их контракт указан в [API.md](API.md). Существующий web-поиск при прошлой выгрузке выполнялся вручную; автономного сборщика поискового индекса в этом проекте нет. После получения evidence:

```sh
python3 catalog.py build --data data/new_run
```

Результаты: `catalog.json.gz`, `catalog.sqlite3`, `products.jsonl`, `coverage.json`, отчёты и отклонённые результаты в `data/new_run/`. Откройте отчёты и сравните фактическое покрытие сетей и ингредиентов; успешный запуск не гарантирует полный ассортимент. Сырые evidence и SQLite игнорируются Git.

## Прямой браузерный сбор для отдельного рецепта

`collect.py` ищет карточки по одному JSON-рецепту в формате [recipe.example.json](recipe.example.json), открывает результаты и сохраняет найденные состав, цену и КБЖУ. Он не обходит проверки и не собирает сразу все рецепты приложения. Если имя работающего контейнера — `camoufox-browser`, и в нём доступны Python, Camoufox и Playwright, можно использовать временную папку внутри контейнера:

```sh
docker exec camoufox-browser mkdir -p /tmp/grocery-recipe
docker cp collect.py camoufox-browser:/tmp/grocery-recipe/collect.py
docker cp recipe.example.json camoufox-browser:/tmp/grocery-recipe/recipe.json
docker exec camoufox-browser python /tmp/grocery-recipe/collect.py \
  --recipe /tmp/grocery-recipe/recipe.json --out /tmp/grocery-recipe/results.json \
  --csv /tmp/grocery-recipe/results.csv --region Москва
docker cp camoufox-browser:/tmp/grocery-recipe/results.json ./results.json
docker cp camoufox-browser:/tmp/grocery-recipe/results.csv ./results.csv
```

`--region Москва` сохраняет подпись региона; он **не выбирает московский адрес на сайте**. Карточки без состава попадают в `rejected_products`, а не в `offers`. Проверяйте журналы и результаты вручную. На последней проверке прямой доступ к Перекрёстку и Пятёрочке возвращал 403; при блокировке используйте разрешённый владельцем источника доступ или ручной импорт, а не объявляйте карточки проверенными.

## Проверка и обновление базы приложения

Обновление снимка API не меняет PostgreSQL. Для существующих карточек приложения используйте отдельные сценарии и порядок из GF `integrations/local-grocery/OPERATIONS.md`: там описаны обновление ВкусВилла через официальный публичный MCP, Магнита через карточки, сохранение сведений о составе, недоступные карточки, цены и бэкап. Для Перекрёстка и Пятёрочки автоматическое актуальное обновление здесь не подтверждено.

Перед применением новых данных проверьте идентификатор товара, источник состава, единицу цены и адрес магазина. Не переносите состав от другого SKU, фасовки или ароматизированного варианта. Состав, выведенный из названия сырого продукта, нужно хранить с пометкой о выводе. Неполный состав, устаревшая цена и неизвестное наличие не должны становиться подтверждёнными автоматически. Вода по рецепту не требует покупки.
